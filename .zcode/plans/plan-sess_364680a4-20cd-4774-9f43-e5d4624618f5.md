按最小改动实现这次“音频文件”功能，我会分 4 块做，尽量不动现有语音生成主流程：

## 1) 让产出的 wav 直接按时间命名保存到 outputs

目标：保留 `artifactId` 作为内部主键，但把真正落盘的 wav 文件改成 `yyyy-mm-dd-hh-mm-ss.wav`。

改动点：
- `core/qwen_tts_engine/storage/paths.py`
- `core/qwen_tts_engine/storage/artifacts.py`
- `core/qwen_tts_engine/server/engine.py`

做法：
- `ArtifactStore.write()` 里生成一个时间戳文件名并写入 `outputs/<timestamp>.wav`。
- sidecar JSON 继续用 `artifactId.json`，但补上 `fileName`、`createdAt` 之类的元数据。
- `ArtifactStore` 启动时从 outputs 目录读取已有 sidecar，恢复历史 artifact 元数据，保证重启后还能列历史文件。
- `get/delete` 仍然按 `artifactId` 访问，但内部会先解析到真实 `fileName`。
- `artifact.created` 事件 payload 也带上 `fileName`，方便前端同步。

这样可以做到：
- 新产出的 wav 是时间戳命名；
- 历史输出能被页面枚举；
- 不破坏现有 `artifactId` 逻辑。

## 3) 新建“音频文件”页面

新建：
- `desktop/src/renderer/src/pages/AudioFilesPage.jsx`

页面结构：
- 顶部：当前选中音频的预览播放器 + 右上角下载按钮
- 下方：单列列表，显示所有 wav 文件，按时间倒序

交互：
- 页面加载时调用新列表 API，读取 `outputs` 目录中的所有 wav。
- 点击列表项：加载顶部播放器预览。
- 下载按钮：调用现有下载逻辑，保存到本地目录。
- 删除按钮：
  - 第一次点：按钮变红/进入确认态；
  - 第二次点：真正删除该 wav 和对应 sidecar，并刷新列表。
- 列表同时监听 `artifact.created`，新文件生成后自动插入。

样式：
- 复用当前页面卡片/标题风格，单列布局。
- 列表项左侧文件名，右侧 download/delete icon 按钮。
- 保持实现简单，页面内 local state 就够，不额外加复杂全局 store。
