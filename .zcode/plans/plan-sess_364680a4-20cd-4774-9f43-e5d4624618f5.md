目标：整理项目目录结构，尤其 `core/qwen_tts_engine`，让职责分组更清楚、便于后续扩展；同时对 desktop 侧做最小但明显有效结构规整。原则：不加新功能，不做大改架构，不碰生成产物 `desktop/dist-electron`，只改源码与必要说明。

实施范围

一、重整 `core/qwen_tts_engine` 目录结构

现状问题
- 当前几乎所有 Python 模块平铺在 `core/qwen_tts_engine/` 下：`artifacts.py`、`jobs.py`、`models.py`、`paths.py`、`protocol.py`、`references.py`、`runtime.py`、`server.py`。
- 这些文件职责已天然分组，但目录未分组，后续扩展会继续堆平铺文件。

改造方案
1. 建立按职责分组子目录
- `core/qwen_tts_engine/runtime/`
  - `__init__.py`
  - `qwen.py`：放 `QwenRuntime`
- `core/qwen_tts_engine/models/`
  - `__init__.py`
  - `registry.py`：模型常量、能力、注册表
  - `install.py`：模型安装/下载/完整性检查
- `core/qwen_tts_engine/storage/`
  - `__init__.py`
  - `paths.py`
  - `artifacts.py`
  - `references.py`
- `core/qwen_tts_engine/jobs/`
  - `__init__.py`
  - `queue.py`
- `core/qwen_tts_engine/server/`
  - `__init__.py`
  - `engine.py`：`EngineServer`
  - `protocol.py`

2. 更新内部 imports
- `__main__.py` 改为从新子包导入 `QwenRuntime`、`EngineServer`
- `server/engine.py` 改为从 `storage` / `models` / `jobs` / `runtime` / `server.protocol` 导入
- `diagnose_custom_voice.py`、`core/tests/test_core.py` 同步改新路径

3. 对外 API 保持尽量稳定
- 在各子包 `__init__.py` 里 re-export 当前主要公共符号：
  - `QwenRuntime`
  - `JobQueue`
  - `RuntimePaths`
  - `ArtifactStore`
  - `ReferenceStore`
  - `install_model` / `list_models` / `get_model` / `get_capabilities`
  - `EngineServer`
  - `EngineError` 等协议对象
- 不改 Python 启动入口名：仍保持 `python -m qwen_tts_engine`
- 不改 Electron 启动契约：`desktop/src/main/engine/paths.js` 仍跑 `-m qwen_tts_engine`

4. `models.py` 做真正拆分，不再单文件塞三种职责
- `registry.py` 放 registry/能力常量
- `install.py` 放下载与完整性逻辑
- `models/__init__.py` 聚合导出
- 这是 core 里收益最大拆分点

二、整理 `desktop/src/main`

现状问题
- `desktop/src/main/index.js` 同时做窗口创建、应用生命周期、IPC 注册、engine 事件转发。
- `ipc/engine.js` 与 `ipc/artifacts.js` 对 artifact 处理边界不清。
- IPC 参数校验/窗口校验逻辑重复。

改造方案
1. 让 `src/main/index.js` 只做组合根
- 保留 app 生命周期主流程
- 把窗口创建提到 `src/main/window/createWindow.js`
- 把 engine 事件转发提到 `src/main/engine/registerEngineEvents.js`
- 可加 `src/main/ipc/registerHandlers.js` 汇总所有 `register*Handlers`

2. 统一 IPC 公共校验
- 新建 `src/main/ipc/common.js`
- 放 `getManager` / `requireString` / `requireObject` / sender/window 校验等公共逻辑
- `engine.js`、`artifacts.js`、`windowControls.js` 复用，去掉重复代码

3. 让 artifact handler 真正归位
- `src/main/ipc/artifacts.js` 收拢全部 artifact 相关 handler
  - `artifacts:get`
  - `artifacts:delete`
  - `artifacts:read`
  - `artifacts:download`
- `src/main/ipc/engine.js` 只保留 engine / models / jobs

三、整理 `desktop/src/preload`

现状问题
- `preload/index.js` 现在是单文件 API 清单。继续长下去会变乱。

改造方案
- 保持 `preload/index.js` 作为唯一 `contextBridge.exposeInMainWorld` 入口
- 新建：
  - `preload/apis/window.js`
  - `preload/apis/telemetry.js`
  - `preload/apis/engine.js`
- 在 `index.js` 里组装导出对象
- 只做文件拆分，不改 API 形状，避免 renderer 额外改动

四、整理 `desktop/src/renderer/src`

现状问题
- 现在按技术类型分目录：`components/`、`pages/`、`store/`、`api/`
- 但 `VoiceGeneratePage.jsx` 已明显是复杂 feature，单文件同时管常量、工具函数、异步流程、UI。
- `TitleBar`、`Sidebar`、`EngineBootstrap`、`TelemetryTracker` 都混在 `components/` 下，壳层组件与业务组件边界不清。
- 路由与 telemetry 对 route/component 常量存在重复定义。

改造方案
1. 增加 feature 分组，但只先落一个最明确 feature
- 新建 `renderer/src/features/voice-generate/`
  - `VoiceGeneratePage.jsx`
  - `constants.js`：`CUSTOM_VOICE_MODELS` / `JOB_STATUS_TEXT`
  - `utils.js`：`toBytes`
- 只拆最明显 page，不全量 feature 化，避免工程化过度

2. 把壳层/启动层从 `components/` 分开
- `renderer/src/layout/`
  - `TitleBar.jsx`
  - `Sidebar.jsx`
- `renderer/src/app/`
  - `EngineBootstrap.jsx`
  - `TelemetryTracker.jsx`

3. 统一路由配置
- 新建 `renderer/src/routes/config.js`
- 集中 route path / label / telemetry route key
- `Sidebar`、`TelemetryTracker`、`AppRoutes` 共用
- 这是小改动，大幅减少重复常量漂移

4. 共享 telemetry 常量
- 新建 `desktop/src/shared/telemetry.js`
- 让 main `ipc/telemetry.js` 与 renderer `api/telemetry.js` 共用 routes/components/event allowlist 常量
- 保持校验逻辑还在各自侧，只提常量

五、文档与路径说明最小同步

- 更新 `core/README.md` 中 `qwen_tts_engine` 内部目录说明，避免 README 仍写平铺结构
- 更新 `desktop/README.md` 中 `src/main` / `src/preload` / `src/renderer` 新分组说明
- 不大规模修古老 architecture docs，避免任务膨胀；只改与当前实际结构最贴近 README

六、实现边界与不做事项

不做
- 不改 `desktop/dist-electron/` 生成产物
- 不重命名根目录 `core` / `desktop`
- 不改 Python 包名 `qwen_tts_engine`
- 不加新功能、不改 IPC 协议、不改业务流程
- 不顺手继续大拆其它页面或做整套 feature-first 全迁移

会做
- 文件迁移、目录分组、最小提取、更新 imports、更新少量 README
- 保持行为等价，重点提升可读性与后续扩展位

实施顺序
1. 先重整 `core/qwen_tts_engine` 子包并修 imports
2. 再整理 main / preload
3. 再整理 renderer 里 `voice-generate`、layout、app、routes/shared telemetry
4. 最后做全局 import/path 自查与 diff review

完成标准
- `core/qwen_tts_engine` 不再一堆职责文件平铺在同层
- main/preload/renderer 目录边界更清楚
- `VoiceGeneratePage` 体积与职责下降
- route/telemetry/IPC 公共常量减少重复
- 无额外功能，无明显工程化膨胀
