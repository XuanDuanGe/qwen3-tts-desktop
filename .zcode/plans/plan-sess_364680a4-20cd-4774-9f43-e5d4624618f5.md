目标：修复 sidecar 首次在 job worker 线程里导入 `torch` / `qwen_tts` 导致的异常卡顿，把重型运行时依赖初始化前移到 Python 进程主线程，同时保持现有“单 sidecar + 单 worker + 单已加载模型 + stdout 仅 NDJSON”的架构不变。

实施方案

1. 在 `core/qwen_tts_engine/runtime.py` 增加显式的“依赖预热”能力
- 提炼当前 `load()` 里懒导入的部分，新增一个只做依赖导入与基础环境探测的方法，例如：
  - 在主线程中 `import torch`
  - `from qwen_tts import Qwen3TTSModel`
  - 保持第三方 stdout 重定向到 stderr，避免污染协议 stdout
  - 记录已有风格的隐私安全日志：开始/完成、torch 版本、CUDA 可用性、内存快照、耗时
- 这个方法不加载具体模型，不调用 `from_pretrained()`，不下载模型，不触碰用户文本。
- `load()` 改为复用这套已预热依赖，而不是每次都重新承担首次重型导入。

2. 在 sidecar 主线程启动阶段执行预热
- 修改 `core/qwen_tts_engine/__main__.py`：在参数解析后、构造 `EngineServer(...)` 之前，调用上面的运行时预热入口。
- 这样可以保证：
  - 首次重型依赖初始化发生在 Python 进程主线程
  - 发生在 `JobQueue` worker 线程创建与实际 `jobs.submit` 执行之前
  - 避免把首次 `torch` / `qwen_tts` 初始化留给 worker 线程
- 若预热失败，让启动像现在的失败路径一样显式失败，交给 Electron `EngineManager.start()` 进入 `unavailable`，而不是把问题延后到首个 job。

3. 保持现有 job 生命周期与模型复用逻辑不变
- 不改 `core/qwen_tts_engine/server.py` 中的单 worker / 单模型复用策略：
  - 同模型仍由 `runtime.is_loaded()` 复用
  - 切模型仍先 `unload()` 再 `from_pretrained()`
- `from_pretrained()` 仍然只在真正首次使用某个模型或切模时发生；修复的是“依赖初始化时机”，不是改成启动即加载某个模型。

4. 补充最小但关键的日志与测试覆盖
- 在 `runtime.py` 中补上预热阶段日志，沿用当前 `[engine] ...` 风格，且只写 stderr。
- 补充/更新 `core/tests/test_core.py` 一类的轻量测试，覆盖：
  - 预热逻辑不会向 stdout 写协议外内容
  - `load()` 会复用已预热依赖入口，而不是再次分散地做首次懒导入
  - 不破坏已有 job 阶段/校验测试
- 如果单元测试不适合直接测真实依赖导入，则通过 mock 验证调用顺序和 stdout/stderr 约束。

5. 按你要求做三层验证，重点证明 Electron 路径恢复正常
- 验证 A：直接脚本
  - 使用现有 `core/diagnose_custom_voice.py`
  - 确认修复后 direct runtime 仍然正常生成 wav
- 验证 B：协议级 sidecar 复现
  - 使用我刚才已经用过的 `python -m qwen_tts_engine` + NDJSON `engine.hello` / `engine.health` / `jobs.submit` 方法
  - 重点确认：
    - 不再停留在只有 `loading model waiting ...`
    - 会出现 `runtime preflight` / `runtime imports completed` / `runtime from_pretrained started` / `completed`
    - 能收到 `artifact.created` 并成功产出 wav
- 验证 C：Electron 端真实调用
  - 启动 Electron 开发应用
  - 走现有页面 `voice_generate`
  - 提交 custom voice 生成
  - 检查 `.local/app-data/logs/...log` 中的时序恢复正常，且 renderer 能拿到 artifact 预览/下载对应 wav

预期结果
- sidecar 首次真实生成前，重型依赖已在主线程初始化完成。
- 首个 `jobs.submit` 不再在 `loading model` 阶段无期限卡住。
- Electron 路径的首次生成耗时会回落到与 direct script / 预热后协议测试接近的数量级。
- 现有架构、隐私边界、stderr 日志约束、stdout NDJSON 协议保持不变。
