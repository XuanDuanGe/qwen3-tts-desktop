## 实现步骤

1. **建立可独立启动的 Python 包**
   - 使用 `python -m qwen_tts_engine` 作为入口。
   - 支持 `--app-data-dir`、`--cache-dir`、`--device`、`--dtype` 参数。
   - 不依赖 Gradio、FastAPI 或项目根目录全局变量。
   - 运行时目录由参数注入，创建 models、outputs、references、temp、logs 和缓存目录。

2. **实现版本化 NDJSON stdio 协议**
   - stdin 按行读取 JSON 请求，stdout 只输出 JSON 协议消息。
   - 支持 request/response/event，保留 request ID 和协议版本。
   - 实现 `engine.hello`、`engine.health`、`engine.shutdown`、`models.list`、`jobs.submit`、`jobs.get`、`jobs.cancel`、`artifacts.get`、`artifacts.delete`、`references.put`、`references.delete`。
   - 普通日志和异常仅输出 stderr，不污染 stdout。
   - 使用稳定错误码，保证 Electron main 可以映射错误。

3. **迁移并解耦 Qwen runtime**
   - 从源项目迁移官方 `Qwen3TTSModel.from_pretrained` 及三种调用：CustomVoice、VoiceDesign、VoiceClone。
   - 保留单模型复用、模型切换卸载、设备缓存清理和采样参数。
   - 不在导入时下载模型；只允许使用已安装的本地模型目录，后续再实现显式下载器。
   - 未安装 `qwen-tts` 或模型未安装时返回结构化错误，而不是让 sidecar 崩溃。
   - 引入 FakeRuntime/无模型健康检查路径，便于 Electron 先验证协议链路。

4. **实现任务、引用和产物边界**
   - 使用单 worker FIFO 队列。
   - 任务状态按 `queued`、`preparing`、`loading_model`、`running`、`writing_artifact`、`succeeded`、`failed`、`cancelled` 管理。
   - 任务取消使用任务级状态，不使用源项目全局中断变量。
   - 参考音频通过受控 `referenceId` 管理，复制到运行时 references 目录，校验基础音频格式，并在删除时清理。
   - WAV 产物使用 UUID 和原子写入，仅返回 `artifactId`、元数据和相对标识，不返回绝对路径或 Base64。

5. **迁移模型注册信息**
   - 将源项目的模型列表转换为稳定的 model ID、repo ID、能力标签和本地目录约定。
   - 根据模型能力校验 CustomVoice、VoiceDesign、VoiceClone 请求，避免错误模型调用。
   - 不迁移原项目的 Gradio UI、HTTP API、全局配置、运行时 pip 安装和仓库根目录写入逻辑。

6. **补充 core README 与最小依赖声明**
   - 说明开发启动命令、协议示例、目录参数和依赖安装方式。
   - 依赖仅声明 `qwen-tts`、PyTorch、Transformers/Accelerate、soundfile 等核心运行库；不引入 Gradio/FastAPI。
   - 在 README 中注明源项目 GPL-3.0 与 Qwen/模型/依赖许可证需要独立审查，避免误导性复制。

7. **Review 与静态检查**
   - 检查 `core/` 中是否残留 Gradio/FastAPI、绝对仓库路径、Base64 音频传输、非 JSON stdout 和源码注释。
   - 执行 Python 语法编译/静态导入检查，不运行真实模型下载、构建或长时间 sidecar。
   - 不修改 `desktop` UI 或 Electron main；后续再按本文档接入 EngineManager。

源项目中的 GPL-3.0 代码会被视为迁移代码保留相应许可证信息；官方 Qwen SDK、模型权重及 PyTorch 的许可证仍需单独确认。
